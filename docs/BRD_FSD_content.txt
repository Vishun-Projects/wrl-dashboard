Background &amp; Context</h1><p>As directed by Sunil Sir, this application addresses a specific operational gap in management review of completed service calls. Branch Managers currently have the ability to approve or reject completed calls in eBizWiz. However, the review cycle in practice runs 3–4 days behind closure — by which time any corrective action (rejection, follow-up with technician, quality escalation) is no longer practically enforceable.</p><p>The root cause is not a missing feature — it is friction. Reviewing calls requires logging into eBizWiz, navigating to the correct module, filtering by branch and status, and manually checking each entry. This friction means reviews happen in batch, days later, rather than in real time when they matter.</p><p>This application removes the friction. It brings completed calls directly to the manager — on their phone or desktop, with one login — so the review happens within hours of closure, not days.</p><p>This is not a replacement for the eBizWiz approval workflow. Branch Managers will still approve/reject in eBizWiz as required. This application is a parallel visibility and annotation layer that enables timely awareness and internal flagging before the formal review window closes.</p><h1>2. Problem Statement</h1><table><tr><td><p><strong>Approval window missed</strong></p></td><td><p>By the time Branch Managers log into eBizWiz to review calls (3–4 days after closure), the technician has moved on and any corrective action is unenforceable</p></td></tr><tr><td><p><strong>No push mechanism</strong></p></td><td><p>eBizWiz requires managers to go find the work — the work does not come to them</p></td></tr><tr><td><p><strong>No annotation without modification</strong></p></td><td><p>Managers cannot flag a concern or add a note without editing the live CRM record</p></td></tr><tr><td><p><strong>No HOD cross-branch view</strong></p></td><td><p>HOD has no single consolidated view without assembling data manually</p></td></tr><tr><td><p><strong>No review audit trail</strong></p></td><td><p>There is no record of when a manager reviewed a call, what they noted, or whether they escalated — creating accountability gaps</p></td></tr></table><h1>3. Objectives</h1><ul><li>Reduce management review lag from 3–4 days to same-day or next-day</li><li>Give Branch Managers a mobile-first view of their branch's recently completed calls immediately after closure</li><li>Enable managers to flag calls (Noted / Query / Escalate) and add internal comments — without touching eBizWiz</li><li>Give HOD a single consolidated view across all branches with cross-branch filter</li><li>Generate downloadable reports of flagged/commented calls for accountability cycles</li><li>Create a written audit trail: who reviewed what, when, and what action was noted</li></ul><h1>4. Core eBizWiz SQL Query</h1><p>This is the parameterised query executed server-side in /api/calls. @office_ids is injected as a safe parameterised value — never string-concatenated. For HOD (office_ids empty), the WHERE office filter is omitted entirely.</p><p>SELECT</p><p>  tc.ncode,</p><p>  tc.vtrnno,</p><p>  tc.dtrndate,</p><p>  tc.dfastclosedatetime,</p><p>  tc.bfastclose,</p><p>  tc.bsolved,</p><p>  tc.dsolvedatetime,</p><p>  tc.vcomplaint,</p><p>  tc.vsolveremarks,</p><p>  tc.brepeatcall,</p><p>  tc.bBMreject,</p><p>  tc.nofficeid,</p><p>  p.vname        AS customer_name,</p><p>  p.vinsttel1    AS customer_phone,</p><p>  o.vcompanyname AS branch_name,</p><p>  ref.vcompanyname AS parent_branch,</p><p>  CASE</p><p>    WHEN EXISTS (</p><p>      SELECT 1 FROM trdcalls2fault f</p><p>      JOIN mstrepair r ON f.nrepair = r.ncode</p><p>      WHERE f.ncalls = tc.ncode AND r.bmajor = '1'</p><p>    ) THEN 'Major'</p><p>    ELSE 'Minor'</p><p>  END AS repair_category,</p><p>  COUNT(*) OVER (</p><p>    PARTITION BY</p><p>      CAST(tc.dfastclosedatetime AS DATE),</p><p>      DATEPART(HOUR, tc.dfastclosedatetime)</p><p>  ) AS hourly_volume</p><p>FROM trhcalls tc</p><p>LEFT JOIN mstparty p   ON tc.nparty    = p.ncode</p><p>LEFT JOIN mstoffice o  ON tc.nofficeid = o.ncode</p><p>LEFT JOIN mstoffice ref ON o.nunder    = ref.ncode</p><p>WHERE</p><p>  tc.bfastclose = '1'</p><p>  AND tc.dfastclosedatetime IS NOT NULL</p><p>  AND tc.dfastclosedatetime &gt; DATEADD(day, -60, GETDATE())</p><p>  -- Branch Manager filter injected here as: AND tc.nofficeid IN (@o1, @o2)</p><p>  -- HOD: filter line omitted entirely</p><p>ORDER BY tc.dfastclosedatetime DESC;</p><p>Performance note: dfastclosedatetime is stored as NVARCHAR(MAX) in eBizWiz. The DATEADD comparison triggers implicit conversion. If query response exceeds 5 seconds in testing, we will pre-fetch with a looser date string filter and do final filtering server-side. This is a known constraint of the source DB design.</p><h1>F6.
